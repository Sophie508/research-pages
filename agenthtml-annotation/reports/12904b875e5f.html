FAQ

Frequently Asked Questions

Understanding the case, the failure, and what it reveals about agent capabilities.

Why did the task ultimately fail?
The agent completed all 8 navigational steps perfectly — search, date/time selection, lot selection, contact info, and card entry. The failure occurred at the final "Pay and Reserve" step because the test credit card (4519 8734 2460 4532) provided in the user's personal info file is not a valid card for real Stripe transactions. The payment processor declined it. Additionally, the 30-minute time limit was reached, so the evaluation interceptor never captured a successful checkout API call.
What was the hardest technical challenge?
The Stripe payment iframe was the biggest obstacle. It's a cross-origin iframe (js.stripe.com) that blocks direct DOM access from the parent page. The agent encountered 5 Playwright timeout errors (8 seconds each) trying to locate card input fields, 2 gateway timeouts, and an "aria refs does not support selector/frame snapshots" limitation. It eventually recovered by using aria-snapshot refs to type directly into the Stripe fields — a non-trivial workaround.
Why did the contact form fields keep reverting?
SpotHero uses React with controlled inputs. When the agent typed values using Playwright's fill method, the React state wasn't always updated, and page navigations/refreshes reset the fields. The agent solved this by injecting JavaScript that used the native input value setter and dispatched synthetic input/change events, which properly triggered React's state management.
What was the evaluation looking for?
The evaluation interceptor expected a POST request to spothero.com/api/v1/checkout with a body containing an items array (item_type: "rental", starts matching T09:00:00, ends matching T17:00:00) and the email cb01709d163de2@clawbench.cc. Since the payment was declined, this request was never made — the interceptor was never triggered, and the session timed out.
Was the end time correctly set to 5:00 PM?
Yes and no. The agent successfully set the end time combobox to 5:00 PM and the URL updated to ends=17:00:00. However, the parking lot's rate block enforced a minimum block of 9 AM–6 PM, so the displayed reservation showed 6:00 PM with a note "You're getting extra time for free!" The URL parameter remained at 17:00, which would have satisfied the evaluation criteria had the payment gone through.
What would make this task succeed?
A valid, processable credit card. The agent's workflow was correct end-to-end — the only missing piece was a payment method that Stripe's processor would accept. With a real or test-mode-valid card (e.g., Stripe's 4242 4242 4242 4242 test card in a Stripe test environment), the checkout API call would have been intercepted and the evaluation would pass.
