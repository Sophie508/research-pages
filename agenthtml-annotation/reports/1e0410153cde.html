The bug report

Options after DATA / PROC break the parser

Valid SAS allows “named options” after a slash on data steps and procedures. The repository’s documentation parser currently rejects that form.

Issue snippet

failing input 
/* from GitHub issue body */
data test / view=testvew;
    set test;
run;

What should succeed

expected behavior

The parser should accept explicit options after / on both:

  • DATA steps — e.g. view=, debug
  • PROC statements — procedure-specific options

Without a grammar production for the options block, tokenization/parse trees fail and documentation extraction aborts.
