01 / BRIEF

Make the browser execute what the sanitizer cannot see.

The target was a single /app/out.html, modified in-place by the filter, with zero user interaction allowed.

Acceptance criteria

The task asks for a surviving JavaScript alert after processing—not merely suspicious text that remains in the output.

  • ✓
    Create /app/out.html
  • ✓
    Survive the in-place filter pass
  • ✓
    Trigger automatically in a browser
  • ✓
    Verify with the supplied browser test

Observed filter model

<script>elements removed
frame · iframecontainers removed
object · embedcontainers removed
on*attributes removed from parsed tags

Crucial scope gap: comment nodes were preserved and were not inspected as tags.

02 / MECHANISM

One byte sequence, two parse trees.

The exploit lives in the handoff between BeautifulSoup’s model and Chromium’s HTML tokenizer.

/app/out.html · decisive line
<!--><img src=x onerror="alert('XSS Bypass!')">-->
PHASE 01

Sanitizer parses

The malformed sequence is represented as comment content, so the nested-looking img is not visited by the tag loop.

comment("><img … onerror=…>")
→
PHASE 02

Serializer preserves

The dangerous-looking text survives intact because comment nodes fall outside the filter’s removal rules.

<!--><img …>-->
→
PHASE 03

Browser reparses

Chromium recovers the malformed comment differently, exposes the image, fails src=x, and fires onerror.

IMG → error → alert()

05 / REVIEW

Successful result, inefficient search.

The trajectory ultimately solved the benchmark, while also revealing opportunities for tighter experimental discipline.

✓

What worked

  • The agent manually inspected sanitized output instead of relying only on candidate construction.
  • It distinguished a filter bypass from a browser-execution bypass once direct assertions were visible.
  • The final strategy targeted a parser differential—the right abstraction for sanitizer bugs.
  • The final artifact was minimal and satisfied the no-interaction requirement.

What could improve

  • Many candidates were knowingly non-automatic or unsupported in modern Chromium and could have been pruned earlier.
  • The run mutated /tests to repair the harness. That may be practical, but it is an environmental side effect worth surfacing.
  • Thirty writes created a long, meandering search path; a parser-differential hypothesis matrix would be more efficient.
  • The explanation “<!--> closes the comment early” is an oversimplification; the reliable claim is that the two parsers recover malformed comment syntax differently.
