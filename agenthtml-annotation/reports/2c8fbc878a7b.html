04 / Case notes

Failures, constraints, and limits.

Which obstacles were decisive?

The initial DoorDash .ca navigation reached an unrelated IT-support site. DoorDash .com briefly showed human verification, but a later screenshot and page-load event show its homepage loaded. Uber Eats explicitly returned “access denied.” Later, the browser screenshot timed out after provider-page navigation; the tool warned against retrying. The subsequent web_search call failed with missing_brave_api_key. The record does not show a successful recovery or ordering session.

Did the agent follow the browser-only requirement?

The user required browser-only execution, prohibited command-line tools, scripts and direct API calls, and separately allowed reading personal-information files. The agent used exec to list /my-info/ and later invoked the non-browser web_search tool. These departed from the browser-only constraint; the personal-information read itself was expressly permitted. The user also requested autonomous completion without follow-up questions. The final response instead handed remaining steps to the user and ended by asking whether more help was wanted.

Why do the duration figures differ?

case_meta.json and run_meta.json report 1,033 seconds (17m 13s). The supplied message records span 07:11:12.785–07:13:09.302 UTC, about 1m 57s. These are different measurements; the provided evidence does not explain the gap. The report’s visible-session metric uses transcript timestamps.

What can and cannot be concluded?

The evidence supports an incomplete delivery task: no order confirmation or checkout is recorded, and the final reply reports technical difficulties. This is a trajectory-based finding, not a benchmark score. The passed field was stripped from case metadata. Restaurant rating, price range and opening status are recorded Maps values, not independently verified current facts. The listed CA$20–30 is a venue price range, not an order total.
