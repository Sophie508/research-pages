03

Where It Broke

What the policy says

  1. A delivered order may be returned — status becomes "return requested".
  2. A delivered order may be exchanged — but only while status is "delivered".
  3. Exchange & modify tools can be called only once; collect all items first.
  4. Returns and exchanges are each one-shot per delivered order.

What the agent did

  1. Confirmed a combined return + exchange plan with one "yes".
  2. Called return_delivered_order_items for the water bottle first.
  3. Order status flipped: delivered → "return requested".
  4. Called exchange_delivered_order_items — rejected: "non-delivered order cannot be exchanged"
  5. Apologized; told customer to come back after the return completes.
Root cause: The agent treated the return and the exchange as independent transactions on a static order. In this domain the order is the state machine — one mutation (return) changes its status, and the next action (exchange) is gated on the prior status. The agent never reconciled the promise against that state transition, so it committed to an impossible sequence.
