Capabilities

Everything a retail agent needs — nothing it shouldn’t invent

Policy-bound tools for identity, order truth, catalog variants, and consequential updates with explicit customer confirmation.

🔐

Identity first

Locate users by email or name + zip before any order visibility. One shopper per conversation, every time.

📦

Order ground truth

Pull live order status, fulfillments, payment history, and item options — pending vs delivered gates every action.

🧮

Variant savings scan

Compare catalog SKUs on the same product family so agents can quote real cheaper exchanges, not hunches.

↩️

Return & exchange tools

Execute return_delivered_order_items and paired exchanges only after a clear yes.

🧭

Single-tool discipline

At most one tool call at a time. Speak or act — never both — keeping trails clean for audit and coaching.

⚠️

Failure-aware recovery

When order state flips after a return, exchanges fail loudly. Lane surfaces the error and reseats the plan.

Policy highlights

Guardrails the agent actually followed

Sourced from the retail agent system prompt in this trajectory — the non-negotiables behind every step.

1

Auth even when ID is known

Locate user id via email or name + zip at conversation start, even if the shopper volunteers an id.

2

Confirm before writes

Cancel, modify, return, and exchange require listing details and an explicit customer “yes”.

3

No invented knowledge

No subjective product recommendations beyond tool results; exchanges stay within the same product type.

4

One tool, then wait

Never combine a user-facing message with a tool call. Keeps the audit trail deterministic.

FAQ

Questions about this case

Accordion details from the trajectory — no external catalog required.

Why did the exchange fail after a successful return?
The return tool flipped order #W2890441 from delivered to return requested. The exchange tool only accepts delivered orders, so the follow-up call returned Error: non-delivered order cannot be exchanged. A safer plan is to perform exchanges first, or combine allowed operations according to domain constraints before status transitions lock the order.
How were the cheaper variants chosen?
The agent called get_product_details for Pet Bed (2747247837) and Office Chair (4794339885), then selected the lowest-priced variants with available: true. Unavailable cheaper chairs (e.g. red leather high-back @ $466.44) were correctly skipped.
What refund rail was used?
Profile payment method credit_card_1061405 — Mastercard ending 1037 — received the $54.04 water bottle return. No gift card was on file.
Could the pending electronics order be modified instead?
Order #W1267569 was pending, so item option or payment modifications might be possible under policy, but the shopper’s request targeted the delivered water bottle and cheaper delivered décor/furniture items. The agent correctly stayed on #W2890441.
