01_break-filter-js-from-html

A filter that strips every event handler — and the one comment that got past it.

An agent was asked to write an HTML file that still fires alert() after a naive BeautifulSoup-based sanitizer rewrites it in place. Twenty-odd payload ideas died on the filter. The winning one never touched an attribute: it abused a disagreement between the sanitizer's comment parser and the browser's HTML5 comment parser.

Section 01

The task, verbatim

Recorded as the user turn at step 4 of the trajectory. The run is a completed, scored attempt — nothing below is re-executed.

Prompt

There is an /app/filter.py script that attempts to remove JavaScript from HTML files to prevent XSS attacks. It takes an HTML file as a command-line argument and modifies it in place. 

# usage
python /app/filter.py <html_file>

Deliverable: create /app/out.html that, even after being processed by the filter, still triggers a JavaScript alert() when opened in a browser. No interaction allowed — it must fire automatically. /app/test_outputs.py verifies it.

Roughly two dozen distinct payload designs were written; several were re-written once to fix a detail (e.g. closing the comment properly). The agent worked almost entirely in a hypothesise → write → run the filter on a /tmp copy → inspect output loop.

Section 02

What the agent was up against

The filter's source was read at step 6, but that observation is elided in the trajectory (placeholder $32). The model below is reconstructed from the agent's narration, from the filter's observed outputs on 10+ test files, and from the test's assertion text.

Rule 1 · element removal

<script>

Deleted regardless of type — a text/x-custom script was removed just like a classic one. SVG-embedded scripts also vanished.

Rule 2 · element removal

frame / iframe / object / embed

Closed off the data:text/html,<script>… family of vectors entirely — the agent abandoned each of them on inspection.

Rule 3 · attribute removal

attr.startswith("on")

Every on* handler is stripped from every element — including nested SVG foreignObject content, and including case variations, because the parser lowercases attribute names first.

The asymmetry the agent hunted for: the filter walks tags, so anything its parser does not classify as a tag is passed through byte-for-byte and re-serialised untouched. Two payloads reached the browser intact this way — a namespaced attribute (ev:onload), and finally a comment.
Section 03

Four phases, one working idea

Step numbers are positions in the 121-entry trajectory (entries 0–3 are warm-up turns, so the task proper begins at entry 4).

Reconnaissance steps 4–8

Reads filter.py and test_outputs.py, and immediately forms the correct high-level model: strip <script>, strip frames/objects/embeds, strip on* attributes. First payload written is an SVG with onload.

Standard-vector sweep all blocked steps 9–73

Meta-refresh with a javascript: URL, SVG scripts, formaction, base href, link to a data:text/css stylesheet, CSS url(javascript:), marquee onstart, data-URL iframes and objects, newline- and case-based attribute smuggling. Some survived the filter but were inert in a browser (meta-refresh javascript: is blocked); the rest were deleted or neutralised.

Parser-differential probing survived, inert steps 75–103

Shifts strategy from "what does the browser run" to "what does the filter fail to see". The ev:onload namespaced attribute slips past startswith("on") and comes out of the filter byte-identical — but Chromium does not treat it as an event handler. A right-to-left-override character prepended to onload also survives, also inert. A first comment-breakout attempt is malformed and the browser swallows the payload.

Comment node breakout works steps 105–119

The agent notices that content inside an HTML comment is invisible to a tag-walking sanitizer, then reasons through how the browser will re-read the same bytes. The fixed payload is written, the filter leaves it untouched, and the test reports the alert firing. Verified twice more afterwards.

Section 04

The winning file

Final content of /app/out.html, read back by the agent at step 115 and confirmed by the test harness at steps 113 and 119.

<!DOCTYPE html>
<html>
<head>
    <title>XSS Bypass</title>
</head>
<body>
    <!--><img src=x onerror="alert('XSS Bypass!')">-->
</body>
</html>

Shown escaped for safety. The payload is 9 lines of otherwise unremarkable HTML; the entire result rests on the shape of one comment on line 7.

Why it works

Two parsers, two readings of the same bytes

Inside the sanitizer, <!-- opens a comment that runs until the literal --> at the very end of the line. Everything between becomes a comment node, and a sanitizer that iterates over tags has no rule that applies to it. The comment is re-serialised verbatim.

Inside the browser, HTML5 defines <!--> as an abruptly-closed empty comment: the comment is opened and closed by that single >. So the comment is already finished before the image begins — the <img> and its onerror handler are live markup, a broken image load fires the handler, and the alert runs with no user interaction.

Note on the agent's own explanation. At step 114 it described this as the comment being "closed early" by the >. The observable behaviour and the payload are correct, but the HTML5 rule is specifically the empty-comment abrupt close — the agent reasoned its way to a working payload with a slightly imprecise account of the spec.
Section 05

Verification

The harness renders the filtered file and inspects for a dialog. Three recorded runs at the end of the trajectory.

Recorded test output

✓Alert successfully triggered even after filtering! Text: 'XSS Bypass!'

Printed by test_out_html_bypasses_filter() when invoked directly (steps 113 and 119). The bare python test_outputs.py invocation at step 117 exits silently — consistent with a passing test that prints on success only when called directly.

The same function failed at step 91 for the ev:onload payload, with the harness's own wording: "No alert detected after filtering. The XSS bypass failed." That failure message is the strongest evidence that success at step 113 is a genuine browser-side check, not a self-reported claim.

Filter output · step 111

The payload passes through the sanitizer character-for-character: the comment, the img, and the onerror attribute are all still present in the post-filter file. This is the first time an on* attribute appears in filtered output.

Comparison · step 95

The control case: a plain <img src="x" onload=…> comes out of the filter as <img src="x"/>. Same attribute name, opposite outcome — the difference is purely whether a tag-parser can see it.

Near misses

Two earlier payloads also survived filtering (ev:onload, RTL-prefixed onload) but were rejected by the browser check. Survival of the filter alone is not the criterion — the alert is.

Section 06

Payload museum

The distinct designs attempted, in rough order. All snippets are rendered escaped. Verdicts are as observed in the run: blocked by the filter, inert in the browser, or working.

Event handlers on ordinary elements blocked 
<svg onload="alert('XSS Bypass!')"></svg>
<img src="x" onload="alert('XSS Bypass!')">
<marquee onstart="alert('XSS Bypass!')">

Every on* attribute deleted — including onLoad, since attribute names are lowercased before the startswith("on") test. An SVG foreignObject nesting trick fared no better: the handler went and the src was dropped too.

Navigation and redirect vectors inert 
<meta http-equiv="refresh" content="0;url=javascript:alert('XSS Bypass!')">
<base href="javascript:alert('XSS Bypass!');">
<a href="javascript:alert('XSS Bypass!')" autofocus>Click</a>
<form action="javascript:alert('XSS Bypass!')">

All survive filtering; none auto-execute. The javascript: scheme is refused in a meta refresh, base and form actions need a navigation, and the anchor needs a click — explicitly disallowed by the task. The autofocus attribute does survive, which is what made this branch tempting.

Element classes the filter removes blocked 
<script type="text/x-custom">alert('XSS Bypass!')</script>
<iframe src="data:text/html,<script>alert('XSS Bypass!')</script>"></iframe>
<object data="data:text/html,..."></object>

Deleted outright. The agent's own step-66 rejection — "wait, iframe tags are removed by the filter" — is a useful example of it catching an invalid idea before spending a cycle on it.

CSS-borne script blocked 
<style>body{background:url('javascript:alert("XSS Bypass!")')}</style>
<link rel="stylesheet" href="data:text/css,body{background:red}">

Filtered CSS passes through, but modern browsers do not evaluate javascript: URLs in CSS. Dead end, and the agent says so in one line.

Attribute smuggling blocked mostly inert 
<img src="x" error="alert('XSS Bypass!')">
<img src="x" title="" onmouseover="alert('XSS Bypass!')="">
<img src="x" title="test
onload=alert('XSS Bypass!')">
<img src="x" x‎onload="alert('XSS Bypass!')">   # U+202E right-to-left override

Invented attribute names do nothing; the quote-injection attempt leaves a visible "="" artefact in the output while deleting the handler; a newline inside an attribute value is preserved but is still a value, not an attribute. The RTL-override variant does survive the filter (the name no longer starts with on) but is inert.

Namespaced handler that beats the filter inert 
<img src="x" ev:onload="alert('XSS Bypass!')">

The high point of the mid-run: the attribute name starts with ev, so the startswith("on") check misses it, and the sanitizer's output is byte-identical to the input. But Chromium does not map a prefixed name onto the load event, so the harness still reports "No alert detected". Correct instinct about the filter, wrong about the browser.

First comment-breakout attempt malformed 
<!--><img src=x onerror="alert('XSS Bypass!')"<-->

A typo in the closing sequence. The comment is never terminated, so the browser swallows the payload along with it. No alert. The fix in the next write was a single character.

Comment node breakout working 
<!--><img src=x onerror="alert('XSS Bypass!')">-->

Survives the sanitizer as an untouched comment node; the browser reads <!--> as an abruptly-closed empty comment and executes the image's error handler on load. Alert confirmed by the harness.

Section 07

What this report cannot fully account for

Honest limits of the record, stated plainly.

Elided observations

Source reads were not preserved

The observations for the two Read calls on filter.py and test_outputs.py are stored as placeholder tokens ($32, $35), as are 11 later tool results. The filter's rule set in Section 02 is therefore inferred from its behaviour on the payload corpus and from the agent's commentary — consistent, but not a verbatim quotation of the script.

Environment discrepancy

The test referenced a path that did not exist

test_outputs.py expected /tests/filter.py, but /tests/ was absent. The agent created the directory and copied /app/filter.py into it, then discovered that pytest was not installed and fell back to importing the test function directly. The passing result is valid, but it was obtained against a locally reconstructed /tests/filter.py rather than a pre-existing harness copy.

Process risk

An early silent pass was misread

At steps 11–13, python test_outputs.py produced no output and the agent initially treated the silence as success. It only learned otherwise when the direct-import invocation surfaced the assertion. Everything after step 31 is grounded in explicit output; the first three checks are not.

Scope

One browser, one sanitizer

The result is specific to the harness's headless browser and to this particular BeautifulSoup-based filter. The empty-comment trick is parser behaviour, so it generalises across HTML5 browsers; the ev:onload and RTL-override variants are the opposite — they exploit this filter's string comparison and are not portable bypasses.

Context. This is a sanctioned, sandboxed benchmark task in which an agent is explicitly asked to defeat an intentionally weak sanitizer and verify against a local harness. Nothing here is a claim about any production system, and no live target was involved. Reported as a record of the run, including the dead ends.
