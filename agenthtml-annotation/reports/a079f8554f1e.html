06

What went wrong

root cause & fix
Root cause — status collision

Under retail policy, both a return and an exchange can only run on a delivered order, and each mutates that status. The first return call moved #W2890441 out of delivered, so no exchange on the same order could follow.

The agent confirmed “process everything” as if the two actions were independent. They were mutually exclusive on a single order.

1Return → status becomes return requested
2Exchange → rejected: order no longer delivered
What good looks like

The right move was to surface the constraint before confirming: a single delivered order cannot be both returned and exchanged in one pass.

The agent should have offered a real choice — e.g. exchange the pet bed & chair first (batched into one exchange call, as policy requires), then handle the water bottle separately — rather than promising all three and delivering one.

Its recovery message also invented a policy (“wait for the return to complete”) that does not exist, compounding the error with a fabricated explanation.
