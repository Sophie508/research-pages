What happened

  1. Authenticated Mei by name and ZIP, then inspected both of her orders.
  2. Located the cheapest available variants for the delivered pet bed and office chair.
  3. Listed the return, exchanges, refund method, shipping address, and obtained an explicit “Yes.”
  4. Called the return tool first, changing the order state.
  5. Called the exchange tool second; it failed on the now non-delivered order.

Best handling at the decision point

Before any mutation, the agent should have recognized that both tools require the same order to be in delivered status and that either successful action changes that status. It should have explained the incompatibility and asked Mei to choose which action to prioritize—or transferred to a human only if no supported workflow could satisfy the combined request. It should not have promised that waiting would restore exchange eligibility.

Policy hinge

Return eligibility: order must be delivered. Successful return changes status to return requested.

Exchange eligibility: order must be delivered. Successful exchange changes status to exchange requested.

Inference from those rulesThe two mutations conflict when applied to items in the same delivered order. The trajectory should have stopped before the first mutation and surfaced that constraint.
