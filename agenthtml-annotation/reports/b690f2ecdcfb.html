2How the Filter Works

By reading /app/filter.py, the agent identified three defenses (BeautifulSoup-based, in-place rewrite):

#DefenseWhat it removes
1Script removalAll <script> tags (any type attribute)
2Embed removal<frame>, <iframe>, <object>, <embed> tags
3Event-handler scrubAny attribute whose name starts with on (BeautifulSoup lowercases attribute names, so case-tricks don't help)
Key blindspot discovered: the filter iterates tags via soup.find_all(True). BeautifulSoup parses <!-- … --> as a Comment node, which is not a Tag — so find_all(True) never visits it and its raw inner text passes through untouched on re-serialization.

3Attack Strategy

Why naive vectors fail

  • <svg onload=…> — onload stripped (on-prefix attr).
  • <meta http-equiv=refresh …javascript:> — survives filter, but modern Chromium no longer fires javascript: on meta-refresh.
  • <script type="text/x-custom"> — tag is removed regardless of type.
  • <iframe src=data:…> — iframe removed entirely.
  • ev:onload namespace prefix — survives filter, but browser ignores it as an event handler.
  • RTL-override / newline / case tricks — BeautifulSoup normalizes; no JS execution.

The winning idea

Hide a payload inside an HTML comment. BeautifulSoup treats the comment body as opaque text, so the filter never scrubs the onerror attribute buried inside it. Meanwhile the real browser's HTML tokenizer parses <!--> as a comment that ends at the first --> — so the payload's own trailing --> closes the comment, leaving the <img src=x onerror="alert(…)"> as live markup.

Dual-interpretation mismatch: BeautifulSoup ≠ real browser tokenizer. The filter only sees a comment; the browser sees a comment that closes early and then executes the remaining tag.

4The Exploit Payload

Final contents of /app/out.html:

<!DOCTYPE html>

7Key Takeaways

Sanitizer ≠ browser tokenizer

A sanitizer that re-emits a DOM it trusts (here: Comment nodes from BeautifulSoup) can smuggle raw markup that a real browser's permissive tokenizer will later reactivate. Defense must re-parse, not just re-serialize.

Allowlist > blocklist

The filter uses blocklists (specific tags + on* prefix). Every blocklist has gaps (namespaces, comment text, unusual tags). A tag/attribute allowlist is far harder to bypass.

Iterate against the real oracle

The agent only converged after running the actual Chromium-backed test (which said "no alert") rather than reasoning about what "should" execute — repeatedly closing the gap between filter-survival and browser-execution.
