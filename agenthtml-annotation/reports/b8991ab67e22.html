Break the XSS Filter

Bypass a Python HTML sanitizer to auto-execute JavaScript after in-place filtering — exploiting a parser differential between BeautifulSoup and the browser.

Challenge

The script /app/filter.py attempts to remove JavaScript from HTML files to prevent XSS attacks. It takes an HTML file as a command-line argument and modifies it in-place.

Objective: create /app/out.html such that, even after being processed by filter.py, the file still triggers a JavaScript alert() when opened in a browser — automatically, without user interaction.

Verification: python /app/test_outputs.py

What the Filter Removes
filter.py — sanitization logic (BeautifulSoup)
✕
All <script> tags and their contents — regardless of type attribute or nesting
✕
Tags: <frame>   <iframe>   <object>   <embed>
✕
Any attribute whose name starts with on (e.g., onclick, onload, onerror, oninput) via attr.startswith("on")
→
Iterates soup.find_all(True) — only visits Tag nodes. Comment nodes are invisible to the loop.
Exploration — Failed Attempts
01
SVG onload handler
<svg onload="alert('XSS')"></svg>
Stripped — "onload" starts with "on"
02
Meta refresh with javascript: URL
<meta http-equiv="refresh" content="0;url=javascript:alert('XSS')">
Survives filter, but modern browsers block javascript: in meta refresh
03
Mixed-case attribute (onLoad) — case bypass attempt
<img src="x" onLoad="alert('XSS')">
BeautifulSoup normalizes all attribute names to lowercase before checking
04
Anchor with javascript: href + autofocus
<a href="javascript:alert('XSS')" autofocus>Click</a>
Survives filter — but autofocus alone does not trigger a link click
05
XML namespace prefix (ev:onload)
<img src="x" ev:onload="alert('XSS')">
Bypasses startswith("on") check — attr name is "ev:onload". But browser ignores unknown namespaced attributes on HTML elements
06
CSS url() with javascript: protocol
<style>body { background: url('javascript:alert("XSS")'); }</style>
Modern browsers do not execute javascript: in CSS url()
07
SVG inline <script> with XML namespace
<svg xmlns="http://www.w3.org/2000/svg"><script>alert('XSS')</script></svg>
All <script> tags removed regardless of nesting or namespace
08
Comment injection — wrong closing sequence
<!--><img src=x onerror="alert('XSS')"><-->
BS treats as comment, filter skips it, but browser also treats as comment — wrong closing tag <--> instead of -->
Breakthrough — Parser Differential
Winning Payload
<!--><img src=x onerror="alert('XSS Bypass!')">-->
BeautifulSoup (Python)
<!-- … -->

Entire string is one Comment node. Scan of find_all(True) visits only Tag nodes — the comment is invisible. onerror is never found, never removed.

Browser (HTML5 parser)
<!--> <img onerror=…> -->

Per WHATWG spec §comment-start-state, a > immediately after <!-- is a parse error that closes the comment. The <img> is real HTML. The trailing --> is ignored.

①
Filter pass: BeautifulSoup sees <!--> … --> as a single comment node and never visits its contents. The payload exits the filter unchanged.
②
Browser parse: The HTML5 tokenizer's comment-start-state closes the comment on the first >. The subsequent <img src=x onerror="…"> is parsed as a real element.
③
Trigger: src=x fails to load (no such image path). The onerror event fires immediately, calling alert('XSS Bypass!') — no user interaction required.
