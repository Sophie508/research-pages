🛠 Root Cause & Expected Fix

The SAS grammar in the sasdocs parser does not account for the dataset/step options clause that follows a / after the dataset name. In SAS syntax:

DATA dataset_name / option=value option2=value2 ;
    ...statements...
RUN;

A proper fix would involve:

  1. Locating the lexer/tokenizer and grammar rules for DATA and PROC statements.
  2. Adding a grammar production that optionally consumes a / followed by one or more option=value pairs before the terminating ;.
  3. Ensuring the AST captures the options so downstream documentation generation reflects them.
  4. Adding test cases with data test / view=testvew; and proc means / alpha=0.05;.

The agent never reached any of these steps because it did not search the repository for the parser implementation.
