SkillLens · coding domain

When an agent gets a skill document, does the score change because of the skill?

Agent benchmarks now ship "skills": short procedural guides that are prepended to a task. A single score difference between "with skill" and "without skill" cannot tell whether the agent used the procedure, was primed by extra domain text, or simply had a lucky run. SkillLens is a diagnostic benchmark built to separate these explanations.

Open the recorded case →Results explorer

  • 1Tasks grouped by procedural bottleneck. 57 coding tasks in 10 capability categories, drawn from public benchmarks and scored by deterministic or external verifiers (0/1), never by an LLM judge.
  • 2Controlled conditions. The same task is run with no skill, the matched skill, a mismatched same-domain skill, same-domain background text, or a skill the model routes to itself.
  • 3Paired diagnostics. Per-task repairs and regressions, category utility and model uptake, instead of one aggregate difference.

How coding tasks entered the benchmark

1 · Categories

Defined by a recurring procedural bottleneck (a reusable workflow, tool convention, diagnostic check), not by benchmark instance.

2 · Skills

One expert-written skill per category, extended with fallbacks for common no-skill failures; audited to exclude task ids, expected answers and verifier logic.

3 · Tasks

Candidates from SWE-bench Lite, BugsInPy, RepoExec, SVEN/CWE, DABench, WebApp1K, AtCoder, BIRD SQL and MLE-bench, kept only if verifiable, not saturated without a skill, and procedurally bottlenecked.

4 · Scoring

Each model–task–condition gets y ∈ {0, 1} from the task verifier; pass rates use a fixed denominator. An LLM judge is used only as a construction-time relevance filter.

Paper§1 L118–123, §3.1 L248–255, §4.2 L437–472, §4.3 L497–528. Headroom is deliberate: the benchmark is diagnostic, "not a random population estimate of domain accuracy" (§4.2 L465–468).

Execution setup for the coding runs

Each task is a Harbor task directory: instruction.md, environment/Dockerfile and tests/test.sh (the verifier). The agent is mini-swe-agent working inside the container; the reward is read from Harbor's result.json. With-skill and without-skill runs use separate task roots (…/with_skill, …/without_skill); the skill text is inserted into the instruction.

Consistency checks

  • For 7 of 8 models, Base / Matched / Routed counts in Table 1 equal the counts recomputed from the per-task file (e.g. Haiku 42 / 49 / 48). The paper's GPT-5.6-Sol row has no per-task data in the repository; the repository's eighth model (HY3-Preview) is not in the paper and is excluded here.
  • Table 3 repairs / regressions and all ten Table 6 category utilities recompute from the per-task file.
  • GLM-5.1: the paper's −1.7 is the difference of two rounded rates (89.5 − 91.2); by counts it is −1/57 ≈ −1.75.

Reruns, missing records and environment issues

  • Log summaryAgent crashes with zero tokens were rerun; timeouts were scored 0 and not rerun. In the case shown, Gemma's N run is a rerun; its M run timed out.
  • Log summary62 of 912 scored rows have no trajectory to inspect (for example GLM-5.1 N: 20, GPT-5.4-Mini M: 21, Kimi-K2.6: 17). Their rewards exist; their runs cannot be replayed.
  • Log summaryVerifier fixes for 10 tasks (handover V3, 2026-05-01); several skills were revised during the pilot. 14 of the 57 tasks pass under N for all 8 models in the saved file, including two tasks whose verifier was fixed; whether headroom was measured before the fix is not recorded.
  • Post-paperEditor's summaryA scan of 870 recorded C0/C1 trajectories (2026-11-01, not in the paper) found 11 runs that read the task's upstream fix from git history, clone or curl; 5 of them then passed. One is Haiku's M run on seaborn-2848, which counts as a repair in Tables 3 and 6. Only SWE-bench tasks have a gold patch to compare against, so other channels were not scanned.

Limits stated in the paper

  • Skill length, wording and helper scripts were not randomized.
  • Results do not extend to long-horizon software engineering; candidate-pool size and distractor quality remain open.
